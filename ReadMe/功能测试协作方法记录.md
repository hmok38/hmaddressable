# 功能测试协作方法记录

收集本轮测试中可用于其他功能和项目的方法。当前是持续补充的素材，不是正式 skill；本轮结束后，再整理 skill 和使用说明。

## 分工与准备

- 助手先读现有工程、配置和文档，列出主测试数量及功能点，复用已有资源和入口，按步骤准备缺少的内容。
- 用户负责约定的构建操作、真实设备操作和结果反馈。日期、环境、版本、提交及执行结果由助手记录，不要求用户填写长表。
- 开测前给一份短清单：隔离的测试环境、工具链、外部服务、设备与权限、测试数据与入口、保存与恢复方式。未满足的条件先解决，再执行依赖它的测试。
- 能从工程读取的信息由助手读取；需要用户配置时，给出准确菜单、字段和填写示例，再读取保存结果，避免反复索要同一信息。

## 每次执行的循环

1. **确认当前状态**：检查准备条件、当前版本和上一步结果；保存可回退的起点，保留用户已有改动，分开记录原有现场与本次准备。
2. **准备当前一步**：助手准备资源、配置和入口，只给用户一个明确操作，不提前堆放后面所有步骤。
3. **接收反馈并检查**：用户完成操作后，助手给出当前要看的结果。优先读取现有日志和产物，只请用户补充无法读取的现象。
4. **决定下一步**：符合预期就记录结果，进入下一步；异常则保留现场，整理最少复现步骤、预期与实际结果。
5. **修复后复测**：定位原因并完成约定范围内的修复，重测失败步骤和直接受影响的功能。通过后更新记录，再恢复原测试顺序。

前置条件或关键证据不足时，暂停依赖它的步骤，继续不受影响的准备。不用重装、清缓存或反复重建来代替定位；确需这些操作时，先保存证据并说明目的。

## 记录规则

- 区分“文件已核对”“用户已确认”“已实际执行”和“待验证”。静态检查、用户确认、构建成功、运行通过分别记录，互不代替。
- 记录以“日期、当前版本或提交、操作、结果、证据位置、下一步”为最小信息；未知项写待确认，不补猜测值。默认由助手维护，不给用户新增表单。
- Git 起点保存工程状态，不代表测试通过。构建产物、服务器内容和设备数据分别记录保存位置，恢复时先核对它们是否属于同一版本。
- 测试环境与正式环境分开；恢复前检查当前修改，不能覆盖未保存的工作。外部服务与设备的变化不能只靠 Git 回退。
- 每次反馈后更新业务执行记录；出现可复用的新方法或旧方法失效时，再补充本文件，避免重复搬运业务细节。

## 本轮已收集的经验

| 日期 | 遇到的情况 | 可复用的处理方法 |
|---|---|---|
| 2026-11-02 | 测试清单和执行表过于复杂，用户执行负担较大 | 先列主测试数量和功能点，再按当前一步推进；环境与过程信息由助手记录。 |
| 2026-11-02 | 只向用户索要配置值，没有说明在哪里填写 | 给出实际操作入口和字段；用户填写后由助手读取，省去重复抄写。 |
| 2026-11-02 | 准备过程中才补充分支、服务和恢复条件 | 将前置检查放在测试用例之前，先确认条件，再开始依赖它们的测试。 |
| 2026-11-02 | 起点包含已有工作和本轮准备，且部分产物不在 Git 中 | 分开提交说明来源；明确 Git 保存范围，产物与外部状态另行归档。 |

以上来自准备阶段。异常定位、修复复测和恢复流程尚待实际测试补充，不能标为已验证有效。

## 测试结束后再做

回看实际有效和失效的做法，去掉项目名称、平台细节、服务器地址及专用资源路径，再整理为 skill：适用范围、输入、分工、执行循环、暂停与完成条件。使用说明保留一个最短启动示例和一个异常复测示例。现在不创建或安装 skill。
