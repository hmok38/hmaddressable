# 功能演示与校验

打开 `Assets/TestScene.unity`。场景已经挂载 `HMAddressableTest`，运行后显示可滚动的演示面板。构建演示程序时，将这个场景作为启动场景加入 Build Settings。

## 资源准备

通过 **HMAA资源管理 → 选择并显示配置表** 配置当前平台。目录名中的 LocalRes、RemoteRes 只是名称，实际本地或远端归属由配置决定；仓库默认配置不保证符合下表，运行完整演示前需核对。

| 演示 | 资源目录 | 配置要求 |
|---|---|---|
| 本地合并 | `Assets/Samples/Test/RES/LocalRes/MultipleTestLocal` | 本地，不加入分散打包列表 |
| 本地分散 | `Assets/Samples/Test/RES/LocalRes/Capsule` | 本地，加入分散打包列表 |
| 远端合并 | `Assets/Samples/Test/RES/RemoteRes/MultipleTestRemote` | 远端，不加入分散打包列表 |
| 远端分散 | `Assets/Samples/Test/RES/RemoteRes/Sphere` | 远端，加入分散打包列表 |
| 本地场景 | `Assets/Samples/Test/SeceneRes` | 本地 |
| 远端场景 | `Assets/Samples/Test/RES/RemoteRes/Scenes` | 远端 |

保留示例原有资源及路径，包括 `LocalRes/New/Cylinder2.prefab`。四项校验以原始示例为基线：Capsule 组只有 `Capsule.prefab` 和 `Cylinder.prefab`，`CapsuleCopy.prefab` 位于 RemoteRes/Sphere。热更后改变成员或路径时，应同步调整校验预期。

填写自己的测试资源服务器地址，关闭强制全部本地和跳过更新。先执行“一键打出包资源(测试包)”，上传 `ServerData/<平台>` 的内容到所填地址对应的平台目录，再构建演示程序。上传时保留子目录；构建程序时沿用这次资源产物。仓库不保存本次测试服务器、母包 state 或构建结果；后续热更应保留自己构建的母包 state 和资源组。

## 按 Label 打包和按组加载

在当前平台配置的目录行选择“按 Label 打包”。“每 Label 资源大小（K）”由本平台所有勾选目录共用，默认 1024，1 K 等于 1024 字节。选择“分散打包”会退出按 Label 打包。

执行母包的分组整理后，打开 Addressables Groups 检查条目。工具按直属资源的文件名升序分片，装得下就放在当前片，超出就从该资源另开一片，单项超限独占一片。勾选目录中每个条目仅保留一个形如 `Assets-TestBundle-Config-part-1` 的 Label。手工 Label 会从这些条目移除。

每次整理都使用当前目标平台和该组的 Bundle 压缩设置。二维贴图按平台尺寸、格式和 Mipmap 计量；同一张图的多个 Sprite 只计一次。音频和视频优先使用导入后的编码大小。文本读取导入后的字节，模型、动画和 Prefab 等使用资源自身当前的序列化对象和外置数据流。场景直接读取自身的 .unity 文件。没有可识别的导入数据时，贴图沿用平台纹理估值，其他资源优先使用已知的导入大小，再回退到自身文件。

未压缩组按数据长度计量。LZ4 组根据当前内容的块内重复数据估算；LZMA 组使用分块 Deflate 近似。已编码的音视频保留导入大小，PCM 音频参与内容估算。估算值不含 Bundle 文件头、跨资源压缩和外部依赖，实际成品可能超过配置值。

每个平台和发布环境都要保存自己的母包分组及 Schemas、原始 state 和累计更新组。母包分片组的 HMLabelPackingSchema 记录了目标平台，热更会检查它。

平台的 BundledAssetGroupSchema Preset 需要开启 `Include Labels in Catalog`。业务启动时可以调用 `await HMAddressableManager.InitializeAsync()`，首次按组或按 Label 加载也会自动初始化。插件在内存里记录已配置分片目录实际发布的 Label，Catalog 继续使用 Addressables 自带的查询键。

以 `Assets/TestBundle/Config` 为例，若 Catalog 中有第 1、2、4 片，`LoadAssetsAsyncByGroup<T>("Assets/TestBundle/Config")` 会查询目录 Label 和这三片，并合并相同的资源位置。`ReleaseResGroup("Assets/TestBundle/Config")` 按同一范围释放。只需要第 2 片时，调用 `LoadAssetsAsyncByLabel<T>("Assets-TestBundle-Config-part-2")`。直接传目录 Label 给这个 Label 接口，也只会命中带该目录 Label 的条目。

热更时，新增资源使用原目录 Label，已有分片资源迁入更新组后保留原 Label。来自分片组的更新组使用 `PackTogether`。更新 Catalog 成功后，插件重新读取分片索引。客户端继续传母包已登记的原目录就能加载新增和迁移的资源。新增业务目录和修改分片目录配置随下一次母包发布。热更整理按原母包 state 中的资源 GUID 和组 GUID 识别新增条目。整理或 Label 校验失败时，插件恢复本次整理前的 Addressables 设置。

按 Label 接口接收已发布的完整 Label。Player 中 Address、GUID 和 Label 共用原生查询键，传入任意 Address 不能用来判断它是否是 Label。构建校验会检查可能让有效 Label 命中其他资源的重名键。

关闭 `Unique Bundle IDs` 时，同一 Bundle 的新旧版本可能无法同时载入。可在启动时先完成热更再加载业务资源。如果同一运行会话中更新已加载的 Bundle，需要先卸载占用旧 Bundle 的资源和场景。

验收分片边界时，可将测试组的 Bundle 压缩设为 Uncompressed，上限设为 1 K，同组放入按名称递增、内容分别为 512、512、1025、1 字节的四个无 BOM 文本资源。母包整理后应依次得到分片序号 1、1、2、3。随后修改第一个资源并新增一个资源，执行一次热更，再修改另一片中的资源做第二次热更。检查原组中未迁移条目的 Label 和新更新组的 Bundle Mode。用原目录加载时，新增和迁移的资源应各出现一次。单独查询某个分片 Label 时，只应返回仍带这枚 Label 的资源。用原目录释放后，再检查这些资源的插件加载句柄已释放，其他目录的句柄仍有效。

要核对压缩估算，可在单独的测试分组放两个各 768 字节的 .bytes 文件，上限设为 1 K。Uncompressed 模式应分成两片。将两个文件都填为重复字节后，以 LZ4 整理应合为一片；换成各自的随机数据后再整理，通常会恢复为两片。这项检查只需整理母包分组。

## 面板操作

| 入口 | 查看什么 |
|---|---|
| 四类加载按钮 | 实例出现，面板显示本次路径及加载结果 |
| 列表、组加载和释放 | 多对象加载；释放后可再次加载；“删除所有对象”只删除场景实例 |
| 更新资源 | 显示进度或结果；失败后按钮变为“重试更新” |
| 加载远端场景 | 替换当前场景，原面板随之消失；建议最后执行 |
| 校验资源加载 | 列表、组、重名地址、并发加载及预下载 |
| 校验资源释放 | 按对象、地址、列表、组释放；检查句柄失效、重载及其他资源不受影响 |
| 校验场景生命周期 | 本地与远端场景的并发加载、延迟激活、卸载及重载 |
| 校验并发更新（Android） | 忙碌时拒绝重复调用、回调归属正确、结束后可再次更新 |

四项校验用于真实 Bundle，在构建后的 Android 程序中依次执行。通过时显示“校验通过”，详细结果写入 `[HMAA校验]` 日志。Editor 直接读取资源的成功结果不能代替打包验证。

“校验资源加载”会清除远端合并示例的依赖下载缓存并重新下载，请使用测试环境并保持联网。并发更新需要首个请求仍在执行；全本地、跳过更新或请求已经结束时，不能证明形成了并发。校验设有 15 秒超时，失败后先保存日志，再重启程序复测。

`Assets/Samples/Test/Scripts/link.xml` 保留校验读取的内部字段，使用 IL2CPP 构建演示时需要随脚本保留。这些入口属于示例，不修改插件对外接口，也不覆盖暂缓处理的同进程旧资源缓存问题。
